# Autosport — Multi-Plan Parallelism Contract

## Shared baseline
Accepted legacy Sections 0–2 provide product/identity baseline. Plans 1–6 may qualify against stable contracts/fixtures without waiting for peer implementation. Fixtures never substitute for PAPER/real/physical evidence.

## Ownership
### Plan 1 — data/causality
Owns domain/data schemas, chronology, historical governance, storage snapshots, collector, event lifecycle, market mirror, replay, outcomes.
Conflict keys: data-causality, chronology, market-state, replay-outcome.

### Plan 2 — financial/PAPER
Owns Decimal odds/money, settlement, EconomicGoal/Risk, Opportunity/PortfolioPlan, PaperBook, scenario truth, portfolio/exposure and financial reconciliation.
Conflict keys: financial-core, paperbook, portfolio-risk.

### Plan 3 — intelligence/research
Owns scientific research/evaluation, opportunities intelligence, models/baselines, agents, durable knowledge, experiential learning, strategy/model factory, supervisor/router, multi-sport intelligence.
Conflict keys: research-science, intelligence, learning-models.

### Plan 4 — providers/execution engineering
Owns capability registry, bookmaker/provider adapters, read-only adapters, execution routing, supervised execution contracts, real-ledger machinery, autonomy guards, browser compatibility harness.
Actionable offline: no real account credentials required.
Conflict keys: provider-bookmaker, execution-adapters, real-ledger-contracts.

### Plan 5 — runtime/security/quality
Owns ProductRuntime, security/session/secrets, forensic evidence/diagnostics, QA/falsifiers, verification-repair plane, endurance/recovery/backup, performance, Windows-lab controller.
Conflict keys: product-runtime, security-evidence, reliability, qualification-control.

### Plan 6 — Windows/UI/release mechanics
Owns localization, Windows/WebView2 semantic shell, complete workflows, source accessibility, packaging/install/update/rollback mechanics.
Conflict keys: windows-ui, accessibility-source, packaging.

### Plan 7 — PAPER/SHADOW convergence
Owns only integration/campaign/freeze of terminal provider-free components. Generic defect returns to owning plan.
Conflict key: paper-shadow-convergence.

### Plan 8 — external/final
Owns real bookmaker/account evidence, supervised/real execution qualification, bounded autonomy authorization/evidence, exact signed final package, physical NVDA and final matrix/handoff.
Conflict keys: external-bookmaker, real-execution, final-release.

## Shared-file rules
Minimize broad edits; refresh main; name conflict key; prefer additive/versioned adapters; converge one shared contract change rather than serializing all workers.

## Hard invariants
- no future leakage;
- exact Decimal financial truth;
- accepted odds/authoritative ticket, not observed quote, are execution truth;
- ACK is not fill;
- UNKNOWN external effect is never blindly retried;
- hard Risk/owner authority is outside model/learning;
- whole-session portfolio, not isolated bet, is economic object;
- no CAPTCHA/geo/auth-security bypass;
- source/PAPER/real/NVDA evidence classes remain distinct.
