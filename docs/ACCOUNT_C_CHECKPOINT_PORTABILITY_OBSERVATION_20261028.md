# GitHub-to-desktop checkpoint portability: not established

A previous simulated campaign artifact had ZIP SHA-256
`da24ca4cbc70ebac731a1433c0c9daa09185785b647bc98f4a2503dc2cb0e5fd`.
Its manifest and simulation boundary pass the read-only artifact audit.
The archive contains a campaign checkpoint, PAPER book and exported independent
authority records. This is simulated line-movement training, not confirmed
match outcomes or proof of profitability.

A local experiment extracted the workspace and authority records to **separate**
directories and pointed `AUTOSPORT_PAPER_EXECUTION_WITNESS_DIR` to the exported
authority. `BlindPaperSandboxCampaign.load` rejected the book because its
independent durable opening witness for the new path was missing. The existing
generation guard binds the book and witness lineage to a snapshot path and
authority root. Repeating the test with the authority inside the workspace was
also rejected because independent authority must be outside the workspace.

Therefore a plain copy of the archived GitHub checkpoint is not an established
way to continue that same training on the user's desktop. The new desktop
sandbox feature can resume its own local checkpoints but does not import this
GitHub policy. Do not rebind or remove witness checks, alter historical records,
or claim GitHub learning was installed. A future portable transfer needs an
explicitly designed and validated import authority, source and digest binding,
fresh-target semantics, and negative/restart tests. It must preserve simulation
truth and avoid granting real-money or model-promotion authority.
