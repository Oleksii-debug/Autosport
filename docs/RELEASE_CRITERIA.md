# Release criteria

## Universal gates for every release candidate

A release candidate is identified by exact source SHA and exact package hash. Required checks must be terminal-green on that exact source. The packaged application, not only a developer-tree run, must launch. Primary keyboard paths must remain operable; useful text must remain visible/selectable/copyable. Machine accessibility checks never substitute for physical NVDA acceptance where a release milestone requires human proof.

No release may claim real provider coverage from fixtures, persistent durability from in-memory tests, or causal integrity without adversarial future-leakage tests. No approximate portfolio calculation may be presented as exact.

## v0.1 minimum gates

Canonical domain/replay/PaperBook tests green on Windows and Linux; semantic/copyability UI tests; runnable Windows shell; deterministic fixture replay; initial bankroll/ticket/settlement flow; no future outcomes exposed before event time; basic persistence/checkpoint or explicit non-durability disclosure until implemented.

## v1.0 additional gates

Measured performance thresholds; persistent high-frequency history; restart/recovery; mature portfolio solver evidence; multi-agent/model gateway recovery; reproducible experiment manifests; packaged Windows smoke from fresh path; exact release manifest/hash; physical Windows keyboard/NVDA acceptance tied to exact package SHA.
