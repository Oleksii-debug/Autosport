# Anti-duplication rule

Before creating a branch/PR or new subsystem, search live repository issues/PRs/branches for the same semantic owner. If useful work exists, repair/converge it. New successors require a concrete incompatibility/blocker. Parallel workers should claim disjoint workstreams from `WORKSTREAMS.md` and share canonical domain contracts. Duplicate reviews, unchanged-head CI and status-only PRs do not earn delivery credit.
