# Дослідницьке порівняння форми й H2H — 4 листопада 2026

## Що реалізовано

Окремий read-only адаптер `causal_strength_h2h.compare` повертає ринкову
оцінку з наявного спостерігача та, за достатньої перевіреної в реєстрі
історії, дві **фіксовані ілюстративні евристики**: форму обох сторін і форму
з H2H. [Дослідницький план](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6630204044)
опубліковано до розробки та запусків. Це не навчена модель, не оцінка
точності, не дозвіл на ставки та не зміна продуктивних компонентів.

Адаптер повторно використовує `feature`, перевірки прив'язаної історичної
ідентичності, `OpponentIntelligenceStore.graph_edges`, його приватні
причинний перегляд записів і `_derive_snapshot_values`. Межа перегляду —
одна мікросекунда до рішення, оскільки канонічний API включає рівний час.
Виключаються поточний ID матчу й безпосередні зустрічі поточної пари з
обох історій форми; H2H рахується окремо наявним спостерігачем. Це запобігає
прямому повторному використанню тих самих ребер у цій формулі, але не доводить
статистичної незалежності решти історії.

Форма використовує ту саму мітку спорту, змагання та контексту матчу; її
блокують невирішені ідентичності, відомі виправлення, невідповідні
історичні аліаси, ID дублі та небінарні scores. Окремо виявляється відоме
виправлення аліаса, яке може зробити раніше стороннє записане ребро
релевантним. Для кожної сторони потрібно щонайменше **два різні опоненти**
і останнє спостереження не старше 30 діб. Канонічний вік зберігається в
цілих секундах; додаткова перевірка межі використовує повну часову точність.
Виклик не перезаписує реєстр або граф.

Для кожної придатної сторони беруться канонічне середнє `m`,
`n_eff = min(кількість рядків, кількість різних опонентів)` і описовий
радіус `1/sqrt(n_eff)`. Радіус **не є довірчим інтервалом**. Далі:

1. `s = (n_eff*m + 5*0.5)/(n_eff+5)` для кожної сторони.
2. `p_form = 0.5 + (s_home-s_away)/2`.
3. Якщо є H2H, `p_form_h2h = (home_wins + 5*p_form)/(n_h2h+5)`;
   інакше комбіноване значення відсутнє.

Вага 5 та інші правила зафіксовані для демонстрації, не оптимізовані та не
обґрунтовують калібрування чи переваги над ринком.

## Тестові приклади та попереднє джерело

В одному **синтетичному** тесті кожна сторона має по два різні попередні
опоненти, а поточна пара має одну окрему попередню зустріч. Отримано
ринкову оцінку 0,625, форму 9/14 і форму з H2H 59/84; ці числа перевіряють
арифметику і не є спостереженнями чи показниками якості.

Зі свіжо розпакованого попереднього [приватного архіву](https://drive.google.com/file/d/1houlefw40Yxhh1qufu7mgVUM3LxhqB9q/view)
перевірено всі 25 записів маніфесту та відтворено обробку **11** раніше
заморожених ринкових оцінок. SHA-256 журналу:
`407bba8c83e854636c74f857609d2954f9f5c92048ec31aff941390a15aee917`.
Ринкові значення збіглися, реєстри залишилися побайтово незміненими.
Оскільки реєстр був явно порожнім, усі 11 прогнозів мали невизначені
ідентичності та утворено **нуль** значень форми чи форми з H2H. Це
повтор старих даних, не незалежна вибірка й не ідентифікація гравців.

Для повтору потрібен той архів, його перевірений маніфест і корінь
`observation`:

```sh
PYTHONPATH=src:experiments/table_tennis_replay python \
  experiments/table_tennis_replay/replay_empty_strength.py observation result.json \
  --expected-forecast-sha256 407bba8c83e854636c74f857609d2954f9f5c92048ec31aff941390a15aee917
```

Адаптер повтору відхиляє непорожні реєстри, інший контрольний хеш журналу,
дубль ID прогнозу та невідповідність ринкової оцінки. Він виводить агрегати,
а не імена чи ID. Документація [MoviOdds](https://moviodds.com/doc) описує
`finished_at` як останнє live-спостереження; це не незалежний доказ часу
завершення. Нових запитів цін або результатів не було.

## Обмеження

Підтвердження `CONFIRMED` у реєстрі саме по собі не доводить реальної
особи, прав чи повноти вихідної історії. Фізичні дублікати з різними ID,
невідомі виправлення і нерозв'язані сторонні ребра можуть залишатися
невиявленими. Перевірка відомих новорелевантних ребер не встановлює повноти
джерела. Приватні API канонічного сховища є залежністю цього експерименту;
продуктивність великого графа та конкурентні зміни двох сховищ не
кваліфікувалися. Жодних реальних ставок, навчання, промоції або оцінки
прибутковості не було.
