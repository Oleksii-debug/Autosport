# Кандидати зіставлення двох джерел — 5 листопада 2026

## Питання та походження

Це ретроспективний огляд уже видимих у веб-пошуку рядків, а не новий
незалежний holdout. [Протокол до автоматизованого порівняння](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6644596870)
зафіксовано після того, як самі фрагменти було переглянуто.

Пошуковий результат для [порівняння Setka Cup](https://tabletennis.setkacup.com/en/participants/2900/compare?compare_with=2819)
показав Petr Wasik і Michal Stibor та дві зустрічі з міткою 19 серпня 2026.
Пряме відкриття тієї самої адреси через доступний веб-читач повернуло тільки
`Loading application...`; тому факти зіставлення взяті з **фрагмента
пошукового індексу**, не з перевіреного поточного вмісту інтерактивної
сторінки. Позначка віку пошукового індексу не засвідчує ні часу публікації,
ні точного стану сторінки на дату матчів. Не отримано оригінальних байтів
повної сторінки або офіційного API-відгуку.

На відкритій сторінці [OG Table Tennis для тієї самої пари](https://ogtabletennis.com/matches/michal-stibor-vs-petr-wasik)
видно два рядки з тією самою календарною міткою та послідовностями очок.
Невідомо, чи бере цей сайт дані з того самого каналу, що Setka; дві сторінки
не доводять незалежних спостережень. Контрольованої повноти списку немає.

Окремий [перелік Празької асоціації](https://www.prazskypinec.cz/zebricek-muzu-psst-12)
містить такі самі імена і роки народження, як відповідні фрагменти Setka.
Це додаткова ознака для ручної перевірки, а не встановлення фізичних осіб:
однакове ім'я і рік народження не є унікальним ідентифікатором. Значення в
асоціативному переліку не переносяться до реєстру Setka, а клуб не
виводиться з назви турніру. У робочому реєстрі жодного аліасу не підтверджено.

На час пошуку індексований фрагмент головної сторінки Setka містив умову
письмового дозволу й посилання для використання матеріалів. Поточну умову
безпосередньо з інтерактивної сторінки та право застосування даних для
навчання не перевірено. Тому сирі таблиці й послідовності очок тут не
публікуються; наявність веб-сторінок не є дозволом на завантаження датасету,
навчання чи перерозповсюдження.

## Результат обмеженого порівняння

У приватний тимчасовий JSON вручну занесено лише два рядки з кожного
фрагмента й запропоновано однозначне зіставлення двох підписів учасників.
Номери `row_id` — локальні посилання на транскрипцію, не ID матчів джерела.
Однаковий календарний підпис, запропоновані учасники та всі очки сетів
утворили **два унікальні кандидати**: в обох випадках відповідний підпис
трапився рівно раз у кожному з вибраних фрагментів. Один із двох кандидатів
мав зворотний порядок сторін. Це не встановлює, що кожна пара рядків описує
одну й ту саму фізичну подію: дві зустрічі можуть мати однаковий рахунок,
дані можуть бути скопійованими, а ручне зіставлення учасників помилковим.

В одній парі текстові годинникові мітки збіглися (`11:15` і `11:15`), в
іншій відрізняються (`12:15` і `12:14`). Мітки порівнюються **як текст**:
невідомі часовий пояс, семантика часу, округлення і причина різниці. Рівність
міток не доводить рівність моментів, а різниця не доводить хвилинної
затримки. У 2+2 вибраних рядках немає незбіглих підписів або груп із
повтореними підписами; це не є оцінкою всього архіву.

Правило валідності партій повторно використовує
`wtt_archive_inventory._score_shape` за **припущення** про best-of-five;
для цих подій формат незалежно не підтверджено. Збіг підпису також не
перевіряє турнір, місце, фізичні ID, первинний результат чи історію
виправлень. Якщо однаковий підпис повторюється в будь-якому джерелі,
програма класифікує всю відповідну групу як неоднозначну і не зливає рядки.
Невідома відповідність учасника виключає такий рядок із порівняння.

## Відтворення та межі доказу

Хеш **власної ручної транскрипції** до видалення її тимчасового файлу:
`940bde1036d591af40998ce76ac68c0746dafa5c805a20d96ab49e3d55c8a580`.
Це не хеш оригінального відгуку джерела й не доказ його вмісту, авторства
або часу. Оригінальні байти та транскрипція не збережені в GitHub чи Drive;
тому повністю незалежно відтворити цей конкретний прогін зі збереженого
вхідного знімка неможливо. Посилання на динамічні сторінки можуть згодом
змінитися. [Агрегат](cross_source_score_candidates_20261105.json) не
містить сирих рядків або імен.

Для нового **дозволеного** локального JSON потрібні точні поля й правила з
`cross_source_score_candidates.py`; приклади повністю вигаданих записів є у
тестах. Вхідний SHA-256 задає користувач, вихід створюється тільки якщо
файлу ще немає:

```sh
PYTHONPATH=src:experiments/table_tennis_replay python \
  experiments/table_tennis_replay/cross_source_score_candidates.py \
  transcription.json aggregate.json --expected-sha256 SHA256_OF_TRANSCRIPTION
```

Окремий квадратичний підрахунок `cross_source_score_reference.py`, прив'язаний
до хешу саме цієї транскрипції, дав 2 попарні збіги, з них 1 зі зворотним
порядком і по одному з однаковою та різною мітками часу. Він перевіряє лише
арифметику зіставлення тих самих введених даних, не правильність ручного
переписування чи незалежність видавців. Два попарні збіги збігаються з
двома унікальними кандидатами тільки для цього обмеженого вводу; при
дубльованих підписах попарний підрахунок може бути більшим.

На Linux/Python 3.12 пройшли **550 тестів** дослідницького каталогу та шести
канонічних наборів, зокрема **16 нових** параметризованих випадків;
`compileall` для нових Python-файлів пройшов. Перевірено зворотні сторони,
збіг і розбіжність годинникових міток, перестановку рядків, неоднозначні
повторні підписи, іншу дату чи рахунок, незнайомі аліаси, неін'єктивне
зіставлення, некоректні поля та змінений хеш. Із локальних Python-файлів
дослідницької поверхні, `src/autosport` і шести канонічних тестів із
`conftest.py` **526** збіглися з батьківським GitHub tree
`5c7a97db4510e024435c9241fc4b25fcf808051f`; три файли нові. Ці тести не
верифікують зовнішні джерела. Статус CI точного коміту зазначається окремо
в issue.

Реальної нової моделі не навчено, жодних ставок не здійснено, портфель і
прибутковість не оцінювалися. Для причинного навчання й реального портфеля
потрібні дозволене джерело з відтворюваними байтами, підтверджені особи та
події, доступність результатів до рішень, історія корекцій, ціни й окрема
незалежна оцінка.
