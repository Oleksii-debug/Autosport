# Зовнішній Elo-проєкт: точність часової межі — 5 листопада 2026

## Межа перевірки

Переглянуто код дослідницького проєкту [Roni-quant/topspin-lab](https://github.com/Roni-quant/topspin-lab/tree/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40)
на зафіксованому commit `ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40`.
Видавець заявляє хронологічне навчання й оцінку міжнародного турніру;
його числа тут **не підтверджуються як незалежний результат**. Це інша
популяція, ніж цільові ліги Setka/Czech Liga Pro, і дані не містять
підтверджених букмекерських цін чи фактичних ставок. [Протокол](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6645828857)
зафіксовано після читання коду, але до синтетичного запуску й інвентаризації
CSV. Дослідження не є новим holdout.

Автор публікує код під [MIT](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/LICENSE)
та зазначає походження спортивних даних з ITTF. Ця ліцензія сама собою не
встановлює прав на первинні результати ITTF, істинності записів або
доступності даних у минулому. Вихідні байти тренувальної історії та
заморожену навчальну модель у каталозі `data/`/`models/` не знайдено;
доступність чи вміст приватної історичної копії автора не перевірено.
Доступ до ITTF API не використовувався, ключі не запитувалися. Код і тести
Autosport не змінюють зовнішній проєкт.

## Що робить код при однаковій мітці часу

У перевіреному commit [`fetch_events.py`](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/pipeline/fetch_events.py#L88)
читає кінець турніру як `event_date`, а [`fetch_matches.py`](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/pipeline/fetch_matches.py#L255)
записує його як `match_date` кожного матчу події. Це не підтверджений час
окремого матчу, рішення або публікації результату.

[`compute_elo.py`](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/pipeline/compute_elo.py#L50)
стабільно сортує рядки за `match_date`, але обробляє рівні значення
послідовно. [`generate_features_v2.py`](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/pipeline/generate_features_v2.py#L71)
також дописує результат кожного рядка в історію перед наступним. Водночас
[методика видавця](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/docs/methodology.md#L5)
описує суворий відбір даних із часом `< t`.

Три точні файли зовнішнього коду перевірено за Git blob і SHA-256; з AST
виконано лише конкретні визначення Elo, розрахунку Elo і форми. Верхньорівневі
імпорти й `main` зовнішнього проєкту, мережеві запити та облікові дані не
використовувалися. В обох вигаданих рядках стоїть однаковий `match_date`,
але є спільний гравець. Зміна тільки результату першого рядка змінила його
Elo перед другим із **1516** на **1484**, а попередню форму з **1** на **0**.
Якщо другий рядок поставити першим, його Elo стає **1500**, попередньої форми
немає. [Машинний результат](external_elo_equal_timestamp_20261105.json).

Отже, реалізація на цьому синтетичному прикладі **не забезпечує суворе
`match_date < t` для рівних міток**. Це не доводить, що конкретний реальний
матч відбувся пізніше за інший або що опублікована метрика обов'язково
спотворена: фактичного часу й оригінального порядку результатів ми не маємо.
Наявні тести Autosport окремо перевіряють невключення результату, доступного
рівно на часовій межі; їх не слід ототожнювати із запуском зовнішньої моделі.

## Межа заявленого freeze

У [README](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/README.md)
вказано дату навчальної історії 16 березня 2026. Однак поточні
[`validate_london_2026.py`](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/experiments/validate_london_2026.py#L43)
та [`retrain_enhanced_rf.py`](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/experiments/retrain_enhanced_rf.py#L19)
фільтрують історію за міткою **раніше 10 травня 2026**. Офіційна
[сторінка ITTF](https://www.ittf.com/tournament/3216/ittf-world-team-table-tennis-championships-finals-london-2026/)
вказує проведення чемпіонату з **28 квітня по 10 травня**. Сам код із такою
межею не доводить freeze на 16 березня чи до початку чемпіонату: для цього
потрібні фактичні історичні вхідні байти та запис часу їх замороження.
Якщо справді використані вхідні дані завершувалися 16 березня, пізніший
фільтр сам по собі не означає їх забруднення. Ми не перевіряли, які події
фактично потрапили до авторського навчального прогону.

## Опублікований CSV прогнозів

Зі [зафіксованого CSV](https://github.com/Roni-quant/topspin-lab/blob/ebe19dd52f0bf6e7353f1fa5442afd2d5e361e40/experiments/london_2026_predictions.csv)
отримано байти з Git blob `7264350b07556cc48bd4dc9c381485c18ca65f54`,
SHA-256 `9bcaa521b50cc573195545094c54601fa8f071b017ea8ed2e8498f076f80b983`.
У **822 рядках** є 443 різні точні джерельні ключі гравців, з яких 369
зустрічаються більше одного разу; 7 неорієнтованих пар повторюються у 14
рядках. Один набір із двох рядків має однакові значення всіх 25 полів. У
CSV немає окремого ID матчу, часу матчу, часу доступності результату чи
ринкових цін. Однакові рядки не доводять дубль фізичної події; жоден рядок
не вилучався. Ключі не ототожнювалися з перевіреними фізичними особами.

Граф точних джерельних ключів має 5 компонент; найбільша містить 432 рядки.
Він побудований на **всьому** опублікованому CSV і годиться лише для
ретроспективного опису, не як ознака на момент історичного рішення або
доказ незалежності. Незалежний попарний/графовий підрахунок на тих самих
байтах відтворив агрегати; він не перевіряє походження чи істинність байтів.
Сирий CSV не входить до Autosport. [Агрегат](external_elo_prediction_inventory_20261105.json)
не містить ідентифікаторів або окремих записів.

## Відтворення

Три файли треба окремо отримати з наведеного вище commit і зберегти в
`source_dir` зі збереженням шляхів. Адаптер не завантажує їх самостійно та
не виконує, якщо хеш не збігається:

| Файл | Git blob | SHA-256 |
| --- | --- | --- |
| `ratings/elo.py` | `de83682c1133539c729b9d795e8b0dca21fa7fc9` | `f27a61edce0c5f0ae2312f4e7077b8426b591289f2351d4ca2fbdfb74026b83b` |
| `pipeline/compute_elo.py` | `0ec21f55337450910d881643ac86ba327680831d` | `a3edf8791b0b1ff645ba7b8cdf6625f5019bbc523544799a05b3b08306d29f79` |
| `pipeline/generate_features_v2.py` | `5e9f34a79189d5f2ff569eb4ebcc34acab106d35` | `3f3464c6ec3b1aed1940ff0829859e7fc16a293ecec99e439d3979120f13073b` |

```sh
PYTHONPATH=src:experiments/table_tennis_replay python \
  experiments/table_tennis_replay/external_elo_causality_audit.py synthetic source_dir synthetic.json
PYTHONPATH=src:experiments/table_tennis_replay python \
  experiments/table_tennis_replay/external_elo_causality_audit.py inventory london_2026_predictions.csv \
  --expected-sha256 9bcaa521b50cc573195545094c54601fa8f071b017ea8ed2e8498f076f80b983 inventory.json
python experiments/table_tennis_replay/external_elo_inventory_reference.py london_2026_predictions.csv
```

Перший режим потребує локальних `pandas` і `numpy` та запускає тільки
перевірені визначення на вигаданому прикладі. Другий повторно використовує
граф точних ключів з `elo_split_graph_audit`; окрема еталонна реалізація
прив'язана лише до зазначеного CSV. Файли результату створюються без
перезапису. Тест без `TT_TOPSPIN_SOURCE_DIR` пропускає запуск зовнішніх
визначень; у зазначеному нижче локальному прогоні змінну було задано й тест
фактично виконано.

На Linux/Python 3.12 пройшов **561 тест**, з них **11 нових**; середовище
синтетичного запуску: pandas 2.2.3, NumPy 2.3.5. Із наявної локальної
Python-поверхні дослідження, `src/autosport` та шести канонічних наборів із
`conftest.py` **529 файлів** збіглися з батьківським GitHub tree
`cbfc71f54cd308b4260efc01060624e7849a3e5b`, три дослідницькі файли нові.
Статус hosted CI точного коміту фіксується в issue. Нова реальна модель не
навчалася; ні фактичну прибутковість, ні право на ставки не встановлено.
