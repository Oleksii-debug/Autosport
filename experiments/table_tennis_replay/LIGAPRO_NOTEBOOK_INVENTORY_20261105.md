# LigaPro: дані та випадковий поділ зовнішнього прикладу

Це описовий аудит джерела та його коду, а не оцінка моделі, новий holdout чи
підтвердження фізичних матчів. [Початковий план](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6649329222)
та [уточнення підписів](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6649364352)
записано до агрегованого порівняння. Код notebook прочитано статично: його не
виконували, модель не навчали й прогнозів або метрик якості не розраховували.

## Джерело та межі

У публічному [репозиторії прикладу](https://github.com/rushilvedantam/table-tennis-match-prediction/tree/cc22670f8e96e9695864493095513abb5b6bc352)
автор описує прогноз завершення матчу після перших двох сетів. Його CSV
`LigaProTableTennis.csv` на зафіксованому commit має 335 346 байтів, Git blob
`be1c7da407abb6435255deae73d10d4523e13b7e`, SHA-256
`375f235115651868337f273939b9094da0189da9f17c3e0432edd2f4041987a4`.
Notebook має 260 884 байти, Git blob
`2a1ceed2798060bef781e2fcddb0596b243f95cb`, SHA-256
`6a32e5114b208281bc57f4fd41a292383cf52cd702f53c5ca0745c730a3a248e`.
Точні байти отримано через GitHub connector і звірено з Git blob; вихідний CSV
тимчасово двічі прочитано на тому самому commit. Вихідні файли та імена не
включені до цього репозиторію.

У корені цього commit є лише README, notebook і CSV; GitHub metadata не
показує ліцензії репозиторію. README називає CSV джерелом, але не встановлює
первинного походження результатів. Пошук знайшов
[обговорення Kaggle](https://www.kaggle.com/general/342364), у якому інший
автор посилається на набір із подібною назвою; сторонній
[каталог](https://www.selectdataset.com/dataset/6d1655afa4b1a87b88ae7475a245d3de)
наводить 4 272 рядки та липень–серпень 2022 року. Це **можливий** напрям
походження, не доведена тотожність файлів: сторінка набору Kaggle не
повернула читабельного вмісту, її байти та ліцензію тут не перевірено.
Права на використання саме цього CSV для навчання та права первинного джерела
не встановлені. Назва LigaPro не доводить країни, місця, складу учасників чи
відповідності цільовим лігам проєкту.

У 16 полях CSV немає явного ID матчу чи гравця, ціни, часу отримання
котирування або часової квитанції окремого результату. `Player1` і `Player2`
використовуються тільки як **точні рядки джерела**, без нормалізації чи
пошуку реальних осіб. У всіх 4 271 очищених рядках розібрані значення `Date`
не мають зазначеної часової зони; межі міток — 2022-07-05…2022-08-02.
Не встановлено, чи є `Date` часом початку матчу, і коли були доступні рахунки
й результат. Перші два сети в notebook — ознаки для рішення **після їх
спостереження**, якщо такий запис був доступний; цей CSV не доводить
своєчасності спостереження. Ознаки не можна автоматично трактувати як
передматчеві.

## Що робить notebook

Статичний код перетворює рахунки на числа, прибирає рядки без потрібних полів,
створює різницю очок за перші два сети та викликає `train_test_split` з
`test_size=0.2`, `random_state=42` і `stratify=HomeWinner`. Пізніші варіанти
додають окремі категоріальні поля двох імен та ознаки години/дня тижня; вони
використовують такий самий параметризований випадковий поділ, а не задану
хронологічну межу. Код розміщує масштабування та one-hot перетворення у
pipeline, що навчається на training-частині. Описано написаний код, не
засвідчено фактичне виконання, версії бібліотек автора чи опубліковані метрики.

Локально повторено **тільки індекси** його очищення й поділу: pandas 2.2.3,
scikit-learn 1.8.0, без `fit`/`predict`. Нова перевірка розподілу самої
таблиці ознак дала ті самі індекси, що й розподіл списку індексів. В інших
версіях бібліотек або в іншому вхідному файлі це не є гарантією збігу.

## Агрегати

| Показник | Значення |
| --- | ---: |
| Усі рядки / після очищення за кодом notebook | 4 272 / 4 271 |
| Умовний training / test | 3 416 / 855 |
| Різні точні рядки імен / різні невпорядковані пари | 360 / 1 943 |
| Повторювані пари / рядки в цих групах | 1 079 / 3 407 |
| Точні рядки імен, наявні в обох частинах | 324 |
| Test-рядки з хоча б одним / двома іменами з training | 855 / 852 |
| Test-рядки з такою самою парою імен у training | 601 |
| Test-рядки, де те саме ім'я є в training із пізнішою міткою | 840 |
| Test-рядки, де та сама пара є в training із пізнішою міткою | 375 |

Останні два показники порівнюють лише наявні naive-мітки `Date` строго `>`;
вони не доводять фактичного часу проведення чи доступності результатів. Один
текстовий рядок може відповідати кільком людям, а одна людина — кільком
написанням. Повтор гравця чи пари не є сам по собі витоком. Разом із
невідомими часами він показує, що цей випадковий поділ **не встановлює
майбутню причинну оцінку** для повторних зустрічей.

У всій очищеній вибірці є **одна** група з **двох** повністю однакових
16-польових текстових рядків і **дві** групи з чотирьох рядків із однаковою
міткою `Date` та невпорядкованою парою імен. На локальному поділі жоден
test-рядок не має в training повністю однакового рядка, однакового підпису
дата–пара–всі рахунки–переможець після перестановки сторін або однакової
пари імен із тією ж текстовою датою/часом. Порожній рахунок залишається
порожнім, а не нулем. Це не доводить відсутності повторних фізичних подій;
підписи не є офіційними ID.

Підрахунки на множинах/словниках звірено окремим прямим попарним пошуком;
простір містив 3 416 × 855 = 2 920 680 можливих пар. Обидва методи читають
ті самі розібрані рядки й не перевіряють джерело незалежно. У
[збереженому агрегаті](ligapro_notebook_inventory_20261105.json) немає
вихідних рядків; 361 різний повний рядок імені з вихідного CSV перевірено
на точну рівність із текстовими значеннями агрегату — збігів немає. Це не
загальний доказ анонімності. Агрегати і вибірка вже були переглянуті, тому
не є матеріалом для незалежної оцінки моделі.

## Перевірки та повторення

На Linux/Python 3.12 пройшли **603 тести**, із них **8 нових**; один опційний
Parquet-тест пропущено через ненаданий `TT_TOPSPIN_PARQUET_DIR`. Синтетичні
тести перевіряють розворот сторін та переможця, порожній рахунок, неоднозначні
імена, однакові й пізні часові мітки, контрольний перебір, формат CSV,
хеш, межу перебору й виключення часових зон із naive-порівняння. `compileall`
двох нових Python-файлів пройшов; 541 Python-файл збігся з батьківським
GitHub tree, два нові. Exact-head CI повідомляється окремо в issue.

Для відтворення потрібен самостійно отриманий файл із наведеного upstream
commit, доступні pandas і scikit-learn в указаних версіях:

```sh
PYTHONPATH=src:experiments/table_tennis_replay python experiments/table_tennis_replay/ligapro_notebook_inventory.py SOURCE_CSV OUTPUT_JSON --expected-sha256 375f235115651868337f273939b9094da0189da9f17c3e0432edd2f4041987a4
```

Вивід створюється лише за відсутності файла. Реєстри ідентичностей, історія,
фінансові модулі та policy не змінювалися; прибутковість не оцінювали,
реальних ставок не здійснювали.
