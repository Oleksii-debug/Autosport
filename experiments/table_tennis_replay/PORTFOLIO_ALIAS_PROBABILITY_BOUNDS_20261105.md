# Умовні межі збитку PAPER-портфеля за гіпотезами про ID

[Протокол](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6656426253)
зафіксовано до нового підрахунку. Цей дослід поєднує раніше проведені
[аналіз можливого збігу ID](PORTFOLIO_ALIAS_SENSITIVITY_20261105.md) та
[точні межі ймовірності програшу всіх квитків](PORTFOLIO_CERTIFIED_JOINT_BOUNDS_20261105.md).
Вхід — ті самі 50 вже переглянутих записів із
[приватного архіву](https://drive.google.com/file/d/1UMioo0IR37vZpfRtct2IiyBt4QhTTMsn/view),
321 389 байтів, SHA-256
`44508bfa10c57033a671277c949ad5bfd1485744a80211497ad9abe91d3971e9`.
Старий повтор створює 41 умовний PAPER-квиток, припускаючи виконання
за показаними цінами. Розглянуто ті самі два ретроспективно вибрані зрізи;
це не незалежний holdout і не нова ставка.

## Питання та припущення

Для кожного точного ID є лише взаємовиключні бінарні результати `home` і
`away`; усі його входження в квитках отримують той самий результат. Для
**ілюстрації** припускається маргінальна ймовірність кожної сторони 1/2;
вона не оцінена з даних або котирувань. Спільна залежність різних ID не
задана й може бути довільною.

У кожному зрізі для кожної невпорядкованої пари різних ID **окремо**
припускається, що вони описують одну подію, спочатку з однаковим, а потім
зі зворотним відображенням сторін. На кожну гіпотезу залишаються лише
сумісні бінарні стани з тими ж маргіналами 1/2. Інші ID між собою не
об'єднуються. Жодне ототожнення осіб чи фізичних матчів не підтверджено;
кількості гіпотез не є їхніми ймовірностями або частотою дублікатів.

Перша подія — **усі відкриті квитки програли**. Друга — **сукупний P&L
відкритих квитків строго менший за нуль**. Для другої події точний
раціональний результат переможного квитка — добуток умовних зафіксованих
коефіцієнтів на умовну ставку мінус ставка; програний квиток дає мінус ставку.
Попередній P&L, комісії, void, повернення та правила прийняття комбінацій
виключено. На відміну від попереднього alias-стресу, стан «жодна сторона не
виграла» тут не моделюється. Якщо дві ноги насправді стосуються одного
матчу, букмекер може відхилити експрес або запропонувати іншу ціну.

## Результати

| Умовна величина | Перший максимум відкритих квитків | Перший максимум спільного точного ID |
| --- | ---: | ---: |
| Відкриті квитки / точні ID | 7 / 8 | 6 / 4 |
| Пар ID / відображень сторін | 28 / 56 | 6 / 12 |
| Базові бінарні стани / стани на гіпотезу | 256 / 128 | 16 / 8 |
| Базова межа для програшу всіх квитків | 0–100% | 0–100% |
| Базова межа для від'ємного P&L відкритих квитків | 50–100% | 50–100% |
| Гіпотези, що звузили межі програшу всіх | 7 / 56 | 7 / 12 |
| Гіпотези, що звузили межі від'ємного P&L | 1 / 56 | 3 / 12 |

Розподіл сертифікованих інтервалів серед **окремих припущень**:

| Подія та інтервал | Перший зріз: кількість відображень | Другий зріз: кількість відображень |
| --- | ---: | ---: |
| Усі програли: 0–0% | 0 | 1 |
| Усі програли: 0–50% | 7 | 5 |
| Усі програли: 0–100% | 49 | 5 |
| Усі програли: 50–100% | 0 | 1 |
| Від'ємний P&L: 50–100% | 55 | 9 |
| Від'ємний P&L: 100–100% | 1 | 3 |

В останньому рядку за відповідної **гіпотетичної** пари й орієнтації кожен
дозволений бінарний стан має від'ємний умовний P&L. Це властивість цієї
обмеженої сітки та припущеної економіки; вона не встановлює, що така пара
існує, що коефіцієнти можна прийняти чи що фактичний портфель матиме саме
такий результат. Значення 50–100% також не є фактичним шансом програшу.
Виграш одного квитка може не покрити ставки на решту, тому дві події різні.

## Як перевірено межі

Використано копії відкритих `PaperTicket`, `PortfolioEngine`, наявний
валідатор сітки та попередню перевірку `Fraction` прямих і двоїстих свідків.
Для кожного стану P&L окремо обчислюється раціонально та звіряється з
`PortfolioEngine.scenario_profit` у межах `1e-24 * max(1, |значення|)`;
знак визначається раціональним значенням, тож нуль не вважається збитком.

Для кожної події та кожного припущення SciPy/HiGHS пропонує пряму і двоїсту
точки лінійної програми. Існуючий перевірювач відновлює дроби зі знаменником
не більше 65 536 і **точно** перевіряє нормування, усі маргінали,
невід'ємність, кожну двоїсту нерівність і рівність цільових функцій. Якщо
хоча б один свідок не проходить перевірку, звіт завершується помилкою без
заяви про доведену межу. Ця межа знаменника може відхилити правильний
розв'язок і не є доказом його відсутності. Повторно перевіряються включення
подій і те, що умовні межі містяться всередині базових. Базові межі для
програшу всіх також звірено з попереднім сертифікованим модулем. Свідки не
зберігаються в публічному агрегаті; перевірити їх повторно можна під час
відтворення з тим самим приватним входом.

Другий, незалежно написаний цикл без LP будує сумісні стани через скорочений
на один ID набір бітів і повторно рахує P&L за `Fraction`. Оскільки
рівномірний розподіл на цій сітці надає кожному стану додатну вагу і
зберігає всі маргінали 1/2, він перевіряє крайні інтервали `0–0%` і
`100–100%` прямим перебором. Для внутрішніх меж доказом залишаються точні
прямий і двоїстий свідки. Обидва способи використовують ті самі умовні
квитки й не є незалежною перевіркою джерельних фактів.

## Джерело та ідентичність

5 листопада 2026 року перевірено публічний опис
[Sportradar Sport Event Competitor Mappings](https://developer.sportradar.com/odds/reference/mapping-sport-event-competitor-mappings).
За документацією, цей endpoint відображає зовнішні ID на ID конкурентів
Sportradar для заданого sport event і лише для провайдерів, налаштованих
для API-ключа; результати мають пагінацію. Це кандидат для подальшої
перевірки, а не доказ, що потрібне джерело доступне чи покрите, і не
ототожнення двох ID матчів. API не викликався, ключ не отримувався;
наявність доступу, ліцензія, фізичні особи та незалежність джерел не
підтверджені.

## Перевірки та відтворення

На Linux/Python 3.12 і SciPy **1.17.0** пройшли **750 тестів, 1 пропущено**;
11 із пройдених — нові. У прогін включено всі TT research-тести й вибрані
тести identity, learning, portfolio, scenario та PAPER snapshot integrity.
Пропущений необов'язковий Parquet-тест потребує ненаданого
`TT_TOPSPIN_PARQUET_DIR`. Для іншого необов'язкового тесту наявні локальні
закріплені функції Elo були передані через `TT_TOPSPIN_SOURCE_DIR`; нових
запитів для нього не було. `py_compile` п'яти змінених/нових Python-файлів
пройшов. Тести охоплюють аналітичні приклади, протилежні сторони, зворотне
відображення, точний нуль, малі додатні й від'ємні P&L, межі перебору,
невдалий solver, непогоджену економіку й свідчення, pin входу, майбутні
результати та незмінність попередніх звітів і вхідних структур.
На локальній тестовій поверхні 564 файли збіглися з батьківським GitHub
tree, один змінено і чотири додано; два додаткові файли — цей звіт і агрегат.

Повторне виконання дало побайтово однаковий
[агрегований JSON](portfolio_alias_probability_bounds_20261105.json),
SHA-256 `e6e8272d1bb0033b604dc1f9e782d59acc73f5fc7dc32793a8a41bfefaf97430`.
П'ять попередніх опублікованих stress-агрегатів відтворено без змін.
Серед рядків-ключів і значень нового агрегату немає точних збігів зі 143
різними ID та іменами вихідного файлу; це не загальний доказ анонімності.
Статус CI точного опублікованого коміту повідомляється окремо в issue.

Для повтору потрібен приватний файл із зазначеним хешем, SciPy та залежності
репозиторію; вихідний файл створюється лише якщо його ще немає:

```sh
PYTHONPATH=src:experiments/table_tennis_replay python experiments/table_tennis_replay/portfolio_alias_probability_bounds_replay.py LIVE_50_JSON OUTPUT_JSON --expected-sha256 44508bfa10c57033a671277c949ad5bfd1485744a80211497ad9abe91d3971e9
```

Результат не є статистичною калібровкою, незалежним forward-випробуванням,
оцінкою прибутковості чи дозволом на execution. Жодного нового реального
навчання, злиття осіб або матчів, API-виклику і реальних ставок не було.
