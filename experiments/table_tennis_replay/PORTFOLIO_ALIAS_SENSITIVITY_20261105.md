# Невідомий зв'язок різних ID у PAPER-портфелі — 5 листопада 2026

Це ретроспективна перевірка умовних сценаріїв на двох уже переглянутих
зрізах, а не пошук чи підтвердження дублікатів матчів. [Протокол](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6647556149)
зафіксовано перед новим розрахунком. Вхід — ті самі 50 записів із
[попереднього приватного архіву](https://drive.google.com/file/d/1UMioo0IR37vZpfRtct2IiyBt4QhTTMsn/view),
321 389 байтів, SHA-256
`44508bfa10c57033a671277c949ad5bfd1485744a80211497ad9abe91d3971e9`.
Повтор створює 41 умовний квиток за раніше відомим правилом; жоден не є
підтверджено прийнятою ставкою. Вхід і вибрані максимуми раніше досліджувалися,
тому цей аналіз не є незалежним holdout.

## Що перевірено

У кожному з двох попередніх зрізів перебрано всі невпорядковані пари різних
точних ID і, окремо для кожної пари, обидва **гіпотетичні** відображення:
`home` на `home` та `home` на `away`. Припускається, що рівно ці два ID
стосуються однієї події; інші ID зберігають попередню сітку станів. Для
пов'язаної пари розглянуто перемогу однієї зі сторін і консервативний стан,
у якому жодна не виграла. Останній не означає void або повернення ставки.
Повторення еквівалентних спроєктованих станів вилучено. Ніяких ваг чи
ймовірностей станам не присвоювали.

Використано наявні від'єднані `PaperTicket`, `PortfolioEngine` і перевірку
попередньої сітки. Для кожного припущення незалежний алгоритм фільтрує
колишню сітку за сумісністю сторін і обчислює результат через `Fraction`;
основний алгоритм будує спільні стани безпосередньо й використовує
`PortfolioEngine.scenario_profit`. Кількість станів, екстремуми й кількість
квитків без можливого виграшу збіглися для кожного відображення; гранична
похибка для значень — `1e-24 * max(1, |значення|)`. Вони використовують ті
самі вхідні квитки та не є незалежним підтвердженням джерела чи фізичних подій.
Якщо консервативна верхня межа роботи перевищує 65 536 перевірок,
умовні екстремуми не обчислюються й не заявляються.

Обидва максимуми охоплення можуть належати різним парам; кожен квиток у сумі
для пари рахується лише раз, навіть якщо містить обидва ID. Верхні й нижні
значення можуть стосуватися різних припущень. Частки відображень — просто
кількість перебраних варіантів, не частота реальних дублікатів чи ймовірність.
Вони не описують усі можливі залежності між іншими подіями.

P&L тут — умовний результат **лише відкритих квитків** за припущених цінах
відносно початкових ставок; попередні розрахунки, витрати, void і правила
конкретного букмекера виключені. Якщо дві ноги справді стосуються одного
матчу, букмекер може взагалі не дозволити таку комбінацію або призначити іншу
ціну. Тому навіть повна сітка не є межею фактичного виграшу чи втрати і не
дозволяє оцінити прибутковість. [Агрегований JSON](portfolio_alias_sensitivity_20261105.json)
не містить імен, ID чи окремих квитків.

## Перевірки та межі

На Linux/Python 3.12 пройшли **579 тестів**, з них **9 нових**; два опційні
тести зовнішніх TT-файлів пропущені, оскільки відповідні файли/змінні
оточення для цього запуску не надано. `compileall` для п'яти змінених або
нових Python-файлів пройшов. Перевірено пряме й зворотне відображення,
протилежні сторони, одночасну появу двох ID в квитку, підрахунок без
подвійної ставки, порожню пару, межу перебору, хеш входу, незмінність
книги та попереднього повтору, майбутні результати й примусову розбіжність
раціональної перевірки. Результат до та після ввімкнення аналізу збігся,
включно з попередніми сценаріями; їхні агрегати також збіглися з двома
раніше опублікованими JSON-звітами. На локальній Python-поверхні 534 файли
збіглися з батьківським GitHub tree; один змінено й чотири нові.
Серед текстових значень агрегату немає точних збігів із 143 різними
джерельними ID та іменами; це не загальний доказ анонімності.

Ідентичність гравців і матчів, права на навчання, фізична незалежність,
доступність та прийняття котирувань не підтверджені. Нових джерельних
запитів і навчання не було, реальні ставки не здійснювалися. Стан CI для
точного опублікованого коміту повідомляється окремо в issue.

Для повтору потрібен приватний `LIVE_50_JSON` із зазначеним хешем:

```sh
PYTHONPATH=src:experiments/table_tennis_replay python experiments/table_tennis_replay/portfolio_alias_sensitivity_replay.py LIVE_50_JSON OUTPUT_JSON --expected-sha256 44508bfa10c57033a671277c949ad5bfd1485744a80211497ad9abe91d3971e9
```

Вихідний файл створюється лише якщо його не існує. Сирі записи залишаються
поза репозиторієм.
