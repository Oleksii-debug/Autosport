Старий повтор формує 41 умовний PAPER-квиток за котируваннями, які лише для
цього повтору вважаються виконаними. Це не новий holdout і не нова ставка.

## Що саме обмежується

Для кожного точного джерельного ID припускаються лише два взаємовиключні
результати `home` і `away`. Одному ID у всіх квитках відповідає один результат.
Для **ілюстрації**, без оцінювання з даних чи цін, кожній стороні кожного ID
задано маргінальну імовірність 1/2. Різні ID не доведено різними фізичними
подіями. Зафіксований простір складається з усіх бінарних конфігурацій;
ніякої статистичної незалежності між різними ID не припускається.

Для цієї сітки знайдено мінімальну і максимальну масу конфігурацій, у яких
**кожен відкритий квиток програє**, серед усіх спільних розподілів із цими
маргіналами. Це не та сама подія, що від'ємний сумарний P&L: виграш одного
квитка може не покрити ставки на інші. Умовні межі не є фактичними шансами,
оцінкою прибутковості, часовим прогнозом або фінансовим дозволом.

## Перевірка математичних меж

Нехай `x[j]` — маса бінарного стану, а `c[j]` дорівнює 1, якщо в ньому всі
відкриті квитки програють, і 0 інакше. Для мінімуму розв'язується
`min c·x` за `A·x=b, x>=0`, де перший рядок `A` складається з одиниць,
решта позначають `home` для відповідного точного ID, `b=(1,1/2,...,1/2)`.
Для максимуму так само мінімізується `-c·x`. Більше восьми ID не перебираються.

Окремий дослідницький адаптер повторно використовує від'єднані
`PaperTicket`, чинну перевірку точних ID та `PortfolioEngine`. Для кожного
стану економіка додатково звіряється з раціональним розрахунком з допуском
`1e-24 * max(1, |значення|)`. Ознака «програли всі» визначається за
результатом **кожного** квитка, не за знаком сумарного P&L.

SciPy/HiGHS використано лише як генератор кандидатів. Після перетворення
запропонованих значень на `Fraction` незалежна перевірка точно вимагає:

1. `x>=0` і `A·x=b`, включно з усіма заданими маргіналами;
2. для двоїстого свідка `y` — `Aᵀ·y<=c` для **кожного** стану;
3. `c·x=b·y` без числового допуску.

Тоді допустимий прямий свідок досягає нижньої межі, доведеної двоїстим;
для максимуму той самий аргумент застосовано до `-c`. Якщо solver не
завершився успішно або раціональне відновлення не пройшло хоча б одну з
точних перевірок, код завершується помилкою і не повідомляє межу як доведену.
Свідки залежать від приватних позицій і не публікуються; їх можна повторно
перевірити з тим самим входом. Межа знаменника відновлення — 65 536: це
консервативне обмеження методу, а не доказ, що жоден розв'язок не існує.

## Результати

| Величина | Перший максимум відкритих квитків | Перший максимум спільного точного ID |
| --- | ---: | ---: |
| Відкриті квитки / точні ID | 7 / 8 | 6 / 4 |
| ID із протилежними сторонами | 0 | 2 |
| Перебрані бінарні стани | 256 | 16 |
| Найменша умовна маса програшу всіх квитків | 0% | 0% |
| Найбільша умовна маса програшу всіх квитків | 100% | 100% |
| Попередній приклад незалежності ID | 75/256 = 29,296875% | 5/16 = 31,25% |
| Попередній приклад «всі home або всі away» | 1/2 = 50% | 0% |
| Ненульові стани у свідках мінімуму / максимуму | 9 / 2 | 4 / 2 |

Отже за самих цих **вигаданих** маргіналів обидва переглянуті портфелі
допускають увесь діапазон від 0 до 1 для події програшу всіх квитків.
Попередні два розподіли — окремі точки всередині діапазону, а не доведені
фактичні залежності. `0%` у сітці не гарантує додатного P&L. Якщо різні ID
насправді стосуються однієї події або існують інші реальні обмеження, не всі
включені конфігурації можуть бути можливими. Навпаки, void, повернення,
неприйняття комбінації та інші правила можуть вимагати розширити модель.
Тому це не межа фактичного фінансового ризику.

## Перевірки та обмеження

На Linux/Python 3.12, SciPy **1.17.0** пройшли **676 тестів**, з них
**10 нових**; один опційний тест пропущено через незаданий
`TT_TOPSPIN_PARQUET_DIR` для читача та Parquet. `compileall` чотирьох
змінених/нових Python-файлів пройшов. Тести охоплюють відомі аналітичні
границі, спільну ногу, протилежні сторони, від'ємний P&L при виграші одного
квитка, пропуск порожнього/надмірного зрізу, невірні вхідні квитки,
підроблені прямі й двоїсті свідки, відмову solver, невідповідність
раціональної економіки, межу майбутнього результату, хеш і незмінність
старого повтору. SciPy — **додаткова залежність лише цього експерименту**;
вона не додана до продуктового ядра. За її відсутності аналіз явно відмовляє.

Базовий повтор і чотири попередні стреси не змінилися при ввімкненні меж;
усі чотири агрегати окремо збіглися з раніше опублікованими JSON. У
перевіреній локальній Python-поверхні 551 файл збігся за Git blob з
батьківським tree `2c0050ba91a2707723bf8daa2ff399eefe716f09`, один
змінено і три додано; `pyproject.toml` також збігся. Серед текстових ключів
і значень [агрегату](portfolio_joint_probability_bounds_20261105.json) немає
точних збігів із 143 різними ID та іменами джерела; це не загальний доказ
анонімності. Стан CI опублікованого коміту повідомляється окремо в issue.

Розрахунок не встановлює фізичні особи чи незалежність джерел, права на
навчання, наявність/прийняття котирувань або реальні результати. Жодних
нових запитів до API, реального навчання, висновку про прибутковість,
промоції чи ставок не було. [Документація MoviOdds](https://moviodds.com/doc)
описує стрічку котирувань і зазначає, що сервіс не афілійований із bet365;
це не підтвердження виконання будь-якої окремої ціни.
