# Ретроспективний стрес спільних ніг PAPER-портфеля

Це аналіз умовних відкритих квитків у раніше переглянутому повторі, не
прогноз, оцінка прибутковості чи доказ прийняття ставки. Моделі не навчалися,
реальні ставки не розміщувалися. [План](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6635514380)
опубліковано перед новим розрахунком, але дані та підсумок старого повтору вже
були відомі, а обидва максимуми обираються заднім числом.

## Джерело й метод

Повторно використано `data/live-50.json` із [попереднього приватного архіву](https://drive.google.com/file/d/1UMioo0IR37vZpfRtct2IiyBt4QhTTMsn/view),
321 389 байтів, SHA-256
`44508bfa10c57033a671277c949ad5bfd1485744a80211497ad9abe91d3971e9`.
Це ті самі 50 раніше переглянутих записів, а не новий holdout. У їхньому
повторі існуюче правило створює 41 умовний квиток із припущеними цінами та
ставкою 1 одиниця; деталі правила та джерела наведено у
[первинному звіті](PORTFOLIO_REPLAY_20261029.md).

До `portfolio_replay.replay` додано необов'язковий агрегований стрес-перегляд.
Він зберігає внутрішні від'єднані копії відкритих `PaperTicket` на **першій**
появі кожного максимуму: (1) кількості відкритих квитків і (2) кількості
квитків зі спільним точним ID. Обидва зрізи обрано ретроспективно за всім
повтором; вони не є рішенням, доступним наперед. Позиції та імена не входять
до [агрегованого результату](portfolio_scenario_stress_20261104.json).

Використано чинний `PortfolioEngine`, `PaperBook` і `PaperRiskPolicy`; нової
фінансової влади або правил відкриття немає. Порівняння повернутого звичайного
повтору до і після ввімкнення стресу збіглося. Окремо звичайний повтор як
структура даних збігся з раніше збереженим `portfolio-replay-report.json`
після вилучення метаданого `input_sha256` із архіву SHA-256
`78d483ead82c645c4443bec5dc07be30a788a60059df71a71e05a364a1c2acbf`.
Це не твердження про побайтову ідентичність JSON-файлів.

Для кожного відкритого квитка сітка умовно задає виграш або програш кожної
вибраної сторони. Повторений точний ключ вибору має спільний стан у всіх
квитках. Якщо за одним точним ID вибрані обидві сторони, їхні виграші
взаємовиключні й додається консервативний стан, де жодна зі згаданих сторін
не виграє. Останній тут рахує обидва вибори програними: це **не** моделює
повернення чи void. Різні ID — лише різні рядки, не встановлені незалежні
події. Для сітки понад 65 536 станів код не заявляє екстремум за вибіркою.

## Два зрізи

| Показник | Перший максимум відкритих | Перший максимум спільного ID |
| --- | ---: | ---: |
| Умовно відкриті квитки / сума ставок | 7 / 7 од. | 6 / 6 од. |
| Різні точні ID / ключі вибору | 8 / 8 | 4 / 6 |
| Найбільше квитків на одному точному ID | 3 | 5 |
| ID із протилежними вибраними сторонами | 0 | 2 |
| Умовних станів сітки | 256 | 36 |
| Мінімум / максимум P&L відкритих квитків у сітці | −7 / +4,00139 | −6 / +0,45745 |

Значення в таблиці — P&L цих відкритих квитків відносно їхніх початкових
ставок за припущених котирувань, **без** раніше розрахованих позицій, витрат,
реальних цін, void/refund і правил конкретного букмекера. Це екстремуми
вказаної абстрактної сітки, не гарантовані межі реальної втрати чи прибутку.
Середнє за сіткою не використовується як математичне сподівання.

Для першого зрізу визначено найбільше падіння сценарного P&L при зміні одного
точного ID з виграшу на програш, коли всі інші вибрані ключі залишаються
виграшними: **4,9125 од.**, у трьох квитках із сумарною ставкою 3 од. Це
різниця з гіпотетичним сценарієм усіх виграшів, включно з недоотриманими
виплатами, не фактична втрата. Для другого зрізу такий сценарій не задається,
бо одночасний виграш протилежних сторін неможливий у цій моделі.

## Перевірка й обмеження

Окремий розрахунок через `Fraction` перебрав ті самі вибрані зрізи та збігся
з екстремумами і допустимим одноподійним стресом у межі
`1e-24 * max(1, |значення|)`. Він використовує ті самі вхідні квитки та
припущення, отже не є незалежним підтвердженням джерела чи фізичних матчів.
Для більш ніж 8 192 станів раціональну контрольну перевірку пропускають і
позначають; основна сітка понад 65 536 також не обчислюється.

Синтетичні тести охоплюють спільну ногу, протилежні сторони, однакові
значення впливу, некоректні ставки й ID квитків, обмеження станів, незмінність
звичайного повтору, ізоляцію майбутніх результатів та відмову при розходженні
з `Fraction`. На Linux/Python 3.12 пройшли **425 локальних тестів**, зокрема
11 нових; п'ять змінених Python-файлів пройшли `compileall`. Стан CI для
точного опублікованого коміту окремо зафіксовано в issue. Документація
[MoviOdds](https://moviodds.com/doc) визначає
`finished_at` як останнє live-спостереження, а не незалежно засвідчений час
завершення. Права на дані, аліаси гравців та матчів, доступність комбінацій,
прийняття ціни й розрахунок букмекером не підтверджені. Немає доведеного
прибутку, реального P&L, кваліфікованого forward-тесту або дозволу на ставки.
