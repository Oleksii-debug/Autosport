# Повернення однієї умовної події у PAPER-портфелі — 4 листопада 2026

Це ретроспективний сценарний аналіз двох **уже вибраних і переглянутих** зрізів, а не новий прогноз чи перевірка прибутковості. [Протокол](https://github.com/Oleksii-debug/Autosport/issues/2591#issuecomment-6639408242) опубліковано перед цим розрахунком. Вхідні байти `live-50.json` із [попереднього приватного архіву](https://drive.google.com/file/d/1UMioo0IR37vZpfRtct2IiyBt4QhTTMsn/view), 321 389 байтів, SHA-256 `44508bfa10c57033a671277c949ad5bfd1485744a80211497ad9abe91d3971e9`, містять ті самі 50 дослідницьких записів. Два зрізи обрані заднім числом: перша поява найбільшої кількості відкритих квитків і перша поява максимуму спільного точного ID. Правила відкриття та попередні результати вже були відомі.

## Метод

Попередня [бінарна сітка](PORTFOLIO_SCENARIO_STRESS_20261104.md) розглядала виграш/програш виборів і не містила void. Новий необов'язковий перегляд використовує ті самі від'єднані знімки відкритих `PaperTicket`, перевірки `PortfolioEngine` та чистий розрахунок `PaperBook._settlement_result`; на синтетичних прикладах він звірений також із публічним `PaperBook.settle`. Вихідний `PaperBook`, рішення й квитки не мутують. Умовне `void` означає тут виключення однієї ноги з добутку коефіцієнтів, а якщо всі ноги квитка виключено — повернення ставки за реалізацією **цього PAPER-модуля**. Програш іншої невиключеної ноги залишається програшем. Це не перевірка правил будь-якого букмекера.

Для кожного точного ID окремо перебираються всі допустимі стани інших точних ID зі старої бінарної сітки. Порівнюється P&L тих самих відкритих квитків, якщо вибраний ID має один із своїх не-void станів, із P&L, коли він void в усіх відповідних квитках. Для протилежних сторін одного точного ID одночасний виграш виключено; додатковий консервативний стан, де обидві вибрані сторони програють, збережено. Значення нижче — **void мінус відповідний не-void сценарій**, решта станів однакова. Точний ID — лише джерельна мітка, не доведена унікальна фізична подія.

Жоден середній результат сітки чи частка знаків не інтерпретується як імовірність або математичне сподівання. Якщо кількість парних порівнянь перевищує 65 536, перебирання не відбувається й екстремуми залишаються невідомими. Всі показані значення — щодо початкових ставок відкритих квитків, без попередніх розрахованих позицій, витрат, реальних цін і правил букмекера. Припускається **рівно один** void ID, а не множинні повернення чи часткові правила. Мінімум та максимум можуть стосуватися різних ID і різних станів інших ніг; це не прогнози та не гарантовані межі реального P&L.

## Результати на раніше переглянутих знімках

| Показник | Перший максимум відкритих квитків | Перший максимум спільного ID |
| --- | ---: | ---: |
| Умовні відкриті квитки / сума ставок | 7 / 7 од. | 6 / 6 од. |
| Різні точні ID | 8 | 4 |
| Задіяні квитки на один void ID, діапазон | 1–3 | 1–5 |
| Повністю перебрані парні сценарії | 2 048 | 144 |
| Мінімум зміни void − не-void | −1,5 од. | −2,19495 од. |
| Максимум зміни void − не-void | +3,46825 од. | +4,2625 од. |

Додатне значення означає лише, що в конкретній **гіпотетичній парі сценаріїв** P&L відкритих квитків за void більший, від'ємне — менший. Воно не є фактичною виплатою або прибутком. Ціни в повторі — припущені показані котирування, не прийняті ставки. [Агрегований JSON](portfolio_single_void_stress_20261104.json) не містить імен, ID чи окремих ніг.

Для кожної пари основний розрахунок звірено з `Fraction` у межах `1e-24 * max(1, |точне значення|)`. Окремо реалізований раціональний перебір за мітками сторін підтвердив кількість пар, екстремуми й кількість додатних/нульових/від'ємних різниць. Він використовує **ті самі** вхідні квитки й правила, тому не є незалежним джерелом. Окремий перебір пропускається понад 8 192 пар і позначається як пропущений; основна перевірка арифметики кожної розглянутої пари при цьому залишається. Результати звичайного повтору та попереднього бінарного стресу структурно збіглися з їхніми контрольними звітами.

## Перевірки та межі

Локально Linux/Python 3.12 пройшли **506 тестів**, із них **14 нових**; `compileall` для п'яти змінених/нових Python-файлів пройшов. Перевірено спільну ногу, повне повернення однієї ноги, іншу програшну ногу, протилежні сторони, межі обчислень, неправильний хеш, незмінність вихідної книги й повтору, змінений майбутній результат і примусову розбіжність контрольного перебору. 507 із 509 існуючих Python-файлів у дослідницькій директорії та `src/autosport` збіглися з батьківським GitHub head; два змінені навмисно, три Python-файли нові; сім додаткових канонічних тестів і `tests/conftest.py` також збіглися. 143 різні точні рядки ID та імен із вхідних матчів перевірено на рівність із текстовими значеннями агрегату: збігів немає (це не загальний доказ анонімності). Стан exact-head CI зазначається окремо в issue; Windows не перевіряли.

[Документація MoviOdds](https://moviodds.com/bet365-table-tennis-odds-api/) описує свої котирування як інформаційні. Особи гравців і фізична унікальність матчів, право використання даних для навчання, незалежність подій, актуальність ціни та її прийняття не встановлені. Нових джерельних запитів, навчання, реальних ставок та оцінки фактичної прибутковості не було.
